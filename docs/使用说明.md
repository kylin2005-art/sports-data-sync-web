| 使用方式 | 入口与适用场景 |
| --- | --- |
| Windows 本机版 | 默认打开 http://127.0.0.1:8766/ ，平台网页登录在这台电脑上完成，适合个人使用。 |

工作台账号用于登录本项目。进入工作台后，再到「平台账号」连接各运动平台。

## Windows 本机启动

1. 安装 Node.js 22.13 或更新版本，并安装 Microsoft Edge 或 Google Chrome。
2. 在项目目录双击 `start.cmd`。首次运行会安装依赖并构建界面，使用期间保持启动窗口运行。
3. 打开 http://127.0.0.1:8766/，进入「平台账号」。连接好来源和目标后，先测试一条活动。

也可在 PowerShell 中运行以下命令。

```powershell
npm.cmd ci --include=dev
npm.cmd start
```

本机版把文件、任务和回执保存在 `%LOCALAPPDATA%\GarminCnTransferWeb\sync.sqlite`。同目录的 `workbench-profiles` 保存浏览器配置，`sessions.dpapi` 使用当前 Windows 用户的 DPAPI 加密。换到其他系统时，在新工作台重新连接平台，再导入需要保留的活动原件。

## Docker 和 Unraid

### 准备 Compose 和密钥

准备能运行 Linux 容器的 Docker 环境和 Compose v2，把项目放在主机上的固定目录。项目已在 Unraid 上安装验证。其他 Docker 主机沿用同一份 `compose.yaml`，按实际访问地址、存储和网络环境修改 `.env`。Unraid 可在主机终端进入项目目录后执行下列命令。

```sh
docker compose version
[ -e .env ] || cp deploy.env.example .env
install -d -m 700 .deploy-secrets
if [ ! -e .deploy-secrets/vault-key ]; then
  key=$(docker run --rm node:22-bookworm-slim node -p "require('node:crypto').randomBytes(32).toString('base64url')") &&
    (umask 077; printf '%s\n' "$key" > .deploy-secrets/vault-key) &&
    chmod 0444 .deploy-secrets/vault-key
  unset key
fi
```

Compose 将密钥文件只读挂进容器。已有安装继续用原密钥，恢复数据也需要它。密钥应单独保管。

在 Windows 上用 Docker Desktop 的 Linux 容器模式时，也可用 PowerShell 准备同样的文件。后续的 `docker compose` 命令可以直接在 PowerShell 运行。

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath 'deploy.env.example' -Destination '.env'
}
New-Item -ItemType Directory -Path '.deploy-secrets' -Force | Out-Null
if (-not (Test-Path -LiteralPath '.deploy-secrets/vault-key')) {
    $vaultKey = docker run --rm node:22-bookworm-slim node -p "require('node:crypto').randomBytes(32).toString('base64url')"
    if ($LASTEXITCODE -ne 0 -or -not $vaultKey) { throw '无法生成凭据密钥。' }
    Set-Content -LiteralPath '.deploy-secrets/vault-key' -Value $vaultKey -Encoding ascii
    Remove-Variable vaultKey
}
```

### 邀请制

在 `.env` 中填写浏览器实际访问的地址。将下方示例域名替换为自己的域名。

```dotenv
GARMIN_WEB_AUTH_MODE=invite
GARMIN_WEB_ORIGIN=https://sync.example.com
GARMIN_WEB_PUBLISH_HOST=127.0.0.1
GARMIN_WEB_PUBLISH_PORT=8768
```

让同一台主机上的 HTTPS 反向代理转发到 `127.0.0.1:8768`，保留浏览器请求的 `Host`。代理如有限制上传大小，设为至少 50 MiB。在主机本机试用时，源地址也可填写 `http://127.0.0.1:8768`。

```sh
docker compose up -d --build
docker compose ps
docker compose exec -T app node multi-user.mjs invite
```

邀请命令会输出注册链接。把它发给对应的人，有效期为 24 小时，每条邀请只能用一次。注册时用户名为 3–32 位，首位用英文字母或数字，其余可用英文字母、数字、下划线或连字符。密码至少 12 个字符，最多 256 字节。

### 个人版内网试用（含 Unraid）

使用空数据卷，或使用原来只有一个账号的工作台数据与原密钥。以下内网地址是示例。把主机地址、网段和执行首次设置的设备地址换成自己的值。

```dotenv
GARMIN_WEB_AUTH_MODE=personal
GARMIN_WEB_ORIGIN=http://192.168.50.10:8768
GARMIN_WEB_PUBLISH_HOST=192.168.50.10
GARMIN_WEB_PUBLISH_PORT=8768
GARMIN_WEB_LAN_SUBNET=192.168.50.0/24
GARMIN_WEB_SETUP_IP=192.168.50.20
```

运行 `docker compose up -d --build`，在指定设备上直接打开上述地址。空数据卷首次访问会提示创建个人工作台账号。设置完成后，同一网段的设备可以用这个账号登录。复用已有单账号数据时，用原用户名和密码登录。

### 个人版启用内网 HTTPS 和佳明授权

在内网 DNS 中把工作台域名指向 Docker 主机。证书须覆盖该域名，访问设备须信任签发证书的 CA。以下以 `sync.home.arpa` 为示例。沿用上一步的网段和首次设置设备配置，在 `.env` 更新这些项。

```dotenv
GARMIN_WEB_ORIGIN=https://sync.home.arpa:8768
GARMIN_WEB_LAN_IP=192.168.50.10
GARMIN_WEB_PUBLISH_HOST=192.168.50.10
GARMIN_WEB_PERSONAL_DI=1
```

在项目目录创建 `compose.tls.yaml`。将本地证书文件放在下面的示例位置，或调整挂载路径。私钥应能由容器运行用户读取，主机端限制其他用户访问。使用内网 CA 时，将其根证书挂入容器并设置 `NODE_EXTRA_CA_CERTS`，供容器健康检查建立 TLS 连接。

```yaml
services:
  app:
    environment:
      GARMIN_WEB_TLS_CERT_FILE: /run/workbench-tls/fullchain.pem
      GARMIN_WEB_TLS_KEY_FILE: /run/workbench-tls/privkey.pem
      NODE_EXTRA_CA_CERTS: /run/workbench-tls/root-ca.pem
    volumes:
      - ./tls/fullchain.pem:/run/workbench-tls/fullchain.pem:ro
      - ./tls/privkey.pem:/run/workbench-tls/privkey.pem:ro
      - ./tls/root-ca.pem:/run/workbench-tls/root-ca.pem:ro
```

```sh
docker compose -f compose.yaml -f compose.tls.yaml up -d --build
docker compose -f compose.yaml -f compose.tls.yaml ps
```

以后管理这套服务时使用同一组 `-f` 参数。换证书后重启容器，让服务重新读取证书链和私钥。个人内网模式按实际 TCP 来源地址限制访问，首次设置请用指定设备直连。 [Docker Compose 配置合并说明](https://docs.docker.com/compose/how-tos/multiple-compose-files/merge/)

## 连接平台账号

登录 Docker 工作台后，会自动检查已保存的账号。到「平台账号」查看结果。明确失效的账号需重新连接。超时、限流等情况会显示「暂无法核验」，原连接仍保留。仅支持上传的平台在实际使用时检查授权。

### 佳明中国和佳明国际

Windows 本机版在对应佳明卡片点「打开官方登录」，在佳明页面登录并完成两步验证，回工作台点「验证登录」。Docker 个人版启用 HTTPS 授权后，从「平台账号」点「授权佳明账号」，选择地区，在佳明官方表单完成登录和两步验证。国区和国际区各授权一次。

Windows 本机版登录国区后如果佳明首页白屏，可以在工作台打开的同一个佳明浏览器窗口中进入 [佳明中国活动页](https://connect.garmin.cn/app/activities)，再回工作台点「验证登录」。如果官网仍在安全验证，先在该窗口完成验证，再重试。

页面显示「已保存」后即可关闭登录窗口。个人版可在授权页点「验证令牌续期」。邀请制默认提供手动凭据配置，佳明授权按个人版的 HTTPS 流程使用。

若佳明登录页空白、被浏览器拦截或验证一直未完成，可在有 Chrome 的 Windows 电脑上，从项目目录启动独立授权窗口。把域名、端口和主机内网 IP 换成工作台实际配置。

```powershell
node tools/garmin-local-auth.mjs https://sync.home.arpa:8768/ 192.168.50.10 garmin
```

跨区可先用「佳明中国 → 国际」选好路线，下载一条原始 FIT，再上传并到目标账号核对。个人版授权页也有「测试一条骑行记录」，可读取国区骑行、下载 FIT，或将选中的一条上传到国际区并确认。

在对应卡片展开「接入说明」，按表单提示连接。Windows 本机版可在同一工作台打开支持的平台官网。在同一内网使用 HTTPS 自托管版时，可在 Windows 上启动独立窗口，登录平台官网后回到卡片点「检查会话」。

```powershell
node tools/garmin-local-auth.mjs https://sync.home.arpa:8768/ 192.168.50.10 platforms
```

## 手动同步和全量任务

### 手动同步几条活动

1. 打开「数据同步」，选择一个来源和一个或多个目标。
2. 点「读取最近 20 条」。需要更早的活动时点「下一页」，再勾选要同步的活动。
3. 只勾选一条可点「测试下载」，到记录中心检查原件。确认文件和目标后点「同步所选」。
4. 在运行日志看每条活动的结果。到「记录中心」下载原件或 Keep 导入文件。有可打开的目标活动链接时，记录旁会显示入口。

### 首次全量，之后增量

创建任务或追加同步目标前，请先连接目标平台。已有任务里的目标掉线后会保留，可在编辑时移除。如果来源和部分目标仍可用，可点「同步已连接目标」手动运行一次，原定时设置和目标不变。

需要把某个平台的历史骑行迁过去时，先选好来源和目标，再点「设置全量骑行同步」。保存任务后，在「定时任务」点「运行」。也可以手动建任务，选择「首次全量，之后增量」和运动类型。只同步骑行时，平台类型不明的活动会单独计数。

首次运行会逐页读平台接口可访问的历史，之后仍检查来源列表，以便发现后来补录的旧活动。已有发送保护的活动会跳过。只想同步最近一批时，任务范围选「仅同步最近指定条数」。定时任务支持每 15、30 或 60 分钟检查，工作台服务需保持运行，平台会话需有效。

### 看懂回执和去重

| 记录状态 | 如何处理 |
| --- | --- |
| 已确认 | 工作台拿到可确认的结果。佳明会保存目标活动编号并按编号读回，确认后可打开目标记录。 |
| 平台已接收、待核对、等待确认 | 佳明回执已有活动 ID 时，点「回查目标记录」查询原目标账号。其他情况请到目标平台检查。若确认没有入库，再点「核对后允许重试」。 |
| 平台判定重复 | 目标接口报告已有该活动，查看目标记录或回执信息。 |
| 待手动导入 | 例如 Keep，下载准备好的文件并在目标 App 导入。 |
| 失败 | 看运行日志给出的具体原因。处理后重新执行任务，明确失败的活动可重试。 |

一次活动发往多个目标时会共享一次下载。去重按来源、目标及其账号区分，也会识别发往同一目标的相同文件。已经确认的目标活动编号还可识别反向同步中的导入副本。遇到结果不明的上传，工作台保留回执，等待核对。

## 骑行分析与分享

1. 从「记录中心」导入 FIT 或 GPX，或先通过同步下载原件。
2. 在文件旁点「分析 / 战报」。也可进「轨迹工具」，勾选一条活动后点「分析并生成战报」。
3. 轨迹表列出文件可用的活动日期、用时、距离、平均功率、平均心率、平均速度和累计爬升。每页 20 条，点表头可排序当前页。`≈` 表示估算，`—` 表示没有可用值。

### 骑行地图与 3D 海拔轨迹

「加载真实地图」会从 OpenFreeMap 读取道路底图，从 Mapterhorn 读取高程。打开后，底图服务会收到当前区域的瓦片请求。可按路线轮廓、速度或功率着色，也可关闭地图的 3D 地形。速度缺失时，符合条件的路段可按距离和时间估算。没有功率记录时功率选项不可用，部分路段缺读数时用灰色表示。

「3D 海拔轨迹」用文件里的定位和海拔绘制。可以拖动视角滑块，也可以点「全屏查看 3D」铺满浏览器窗口。在全屏界面，分享范围默认是「仅查看」，选好「隐藏起终点附近」或「完整路线」后可下载或分享 1440 × 840 PNG。

### 骑行探索地图

在单次活动的「骑行探索」点「加载探索地图」。绿色是这次首次骑到的格子，蓝色是这次之前已骑过的格子。地图从本次活动开始显示，点「查看全部格子」可缩放到此前骑过的区域。

升级后首次生成索引时，历史文件较多的工作台可能需要等待一分钟或更久。建好的格子索引随数据卷保存，重启后可直接使用。导入新 FIT 或 GPX 后，下一次打开探索地图只计算未建索引的文件。

每个原始定位点会点亮所在的格子，同一个格子重复经过只计一次；两个点之间没有记录的位置不补算。格子的地图投影尺寸为 500 米，地面边长随纬度变化。优先以活动时间判断先后；活动时间缺失时按存档先后判断。已标记为跑步等其他运动的文件、没有 GPS 的活动和坐标系不兼容的轨迹不会点亮格子。没有运动类型标记的 GPX 也会按轨迹参与计算。补导入有时间的旧活动后，再打开探索地图会更新统计。

「下载探索卡 PNG」可保存 1080 × 1080 图片。「分享探索卡」会打开浏览器的系统分享面板，设备不支持时改为下载。图片只含格子统计，地图、日期和路线不会写进图片。探索地图只在打开时向底图服务请求瓦片；底图不可用时会尝试仅显示格子和轨迹。

### 月度骑行明信片

进入「轨迹工具」，在「月度骑行明信片」选择月份并点「生成月报」。月份按浏览器时区划分，只统计可定位且有活动时间的骑行。蓝色越深，代表当月骑过该格子的次数越多。同一文件内，每个格子最多计一次。文件内容完全相同时会合并为一份存档，同一骑行由不同平台重新导出时可能计为多趟。

代表骑行是当月覆盖格子最多的一趟，覆盖数相同则选时间较早的一趟。页面会把它和当年此前月份的单次最高覆盖数比较。点「分析这趟骑行」可查看原活动。

明信片可下载或分享为 1080 × 1440 PNG，默认只显示月份、覆盖统计和代表骑行的格子数。工作台里的真实热图不会写进图片。勾选「添加裁剪后的代表路线」可加入去掉起终点附近的轮廓。熟悉当地路线的人仍有可能认出这段轮廓。

### 生成分享图

选「暗夜竞速」或「白昼画报」，再选 3:4 或 9:16。两种 PNG 分别为 1080 × 1440 和 1080 × 1920。路线和日期默认隐藏。显示路线后，文件有连续海拔时可选 3D，或切换到 2D 轮廓。3D 视角在分析区、战报和全屏视图之间同步。

「隐藏起终点附近」只绘制处理后的路线。熟悉当地路况的人仍可能从轮廓认出位置。分享前可检查标题、日期和路线范围。点「下载战报 PNG」会保存图片，点「分享战报图片」则在支持文件分享的浏览器上打开系统分享面板。浏览器不支持时，改为下载 PNG。

多选文件可预览或叠加轨迹，并导出透明 PNG。合并 GPX 需要轨迹点有有效时间和可合并的坐标系。合并后的文件存入记录中心。FIT 转 GPX 会保留能表示的字段，原始 FIT 仍可单独下载。

临时定位记录需要浏览器定位权限。选择运动类型后点「开始记录」，记录时保持页面开启。停止后可保存 GPX。

## 排查、更新和备份

| 遇到的情况 | 检查方式 |
| --- | --- |
| Windows 页面打不开 | 确认 `start.cmd` 窗口仍在运行，检查启动输出和端口。依赖有变更时先运行 `npm.cmd ci --include=dev`。 |
| Docker 登录页返回 403 | 核对浏览器地址的协议、域名和端口与 `GARMIN_WEB_ORIGIN` 一致。走反向代理时检查 `Host`，个人内网首次设置时检查指定设备 IP。 |
| 容器没有就绪 | 用 `docker compose ps` 和 `docker compose logs --tail=80 app` 检查启动。`/healthz` 返回 503 时，检查数据卷恢复情况和凭据密钥。健康检查连不上 HTTPS 时，检查域名和证书信任链。 |
| 佳明授权后一直未保存 | 确认地区和两步验证，回授权页查看结果。官网页卡住可改用独立窗口。窗口关闭前先确认工作台显示「已保存」。 |
| 同步中遇到限流、登录失效或文件失败 | 按运行日志核对。浏览器版佳明列表遇到部分 403 / 304 会重试。连续两条原始文件下载返回 406 时会停止本批。先检查平台会话或换一条可下载的活动，再运行任务。 |
| 有接收回执，但目标暂时找不到活动 | 到目标平台核对，等异步导入完成后再处理。确认确实没有入库时，可在记录中心允许重试。 |
| 3D、功率选项不可用或地图空白 | 查看文件有没有 GPS、海拔和功率数据。真实地图需能访问瓦片服务。地图未加载时仍可使用工作台内的轨迹预览和战报。 |

Windows 更新前先关闭启动终端，确认服务已停止，再备份 `%LOCALAPPDATA%\GarminCnTransferWeb`。替换代码后重新安装依赖并启动。Docker 更新在项目目录执行 `docker compose up -d --build`。使用 TLS 覆盖文件的部署继续带上相同的 `-f` 参数。

Docker 备份应先停止工作台，再复制整个数据卷。默认项目名生成 `sports-data-sync_data`，若改过项目名，请先确认实际卷名。下例把该卷只读挂载，并按时间生成备份文件。

```sh
docker volume inspect sports-data-sync_data >/dev/null &&
  docker compose stop app &&
  install -d -m 700 backups &&
  docker run --rm \
    -v sports-data-sync_data:/data:ro -v "$PWD/backups:/backup" \
    node:22-bookworm-slim tar -czf "/backup/workbench-$(date +%Y%m%d-%H%M%S).tgz" -C /data .
```

备份完成后用 `docker compose start app` 恢复运行。另存 `.deploy-secrets/vault-key`、部署配置和证书。

迁移到新主机时，先放好原密钥和部署配置，再把备份解压到一个临时目录。把下方路径替换为解压后的目录。恢复命令要求源目录包含 `auth.sqlite`，且目标卷尚无账号数据库。

```sh
docker compose build app
docker compose run --rm --no-deps --user 0 \
  -v /absolute/path/to/restored-data:/migration:ro app \
  sh -c 'test -f /migration/auth.sqlite && test ! -e /data/auth.sqlite && cp -a /migration/. /data/ && chown -R node:node /data && chmod 0700 /data'
docker compose up -d
```

恢复后先登录核对任务和活动文件，再验证平台会话。用 `docker compose down` 可以停止服务并保留数据卷。每个数据卷由一个实例运行定时任务。
